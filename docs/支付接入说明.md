# 支付接入说明

## 当前方式：销售页下单、二维码与人工核实

新官网仅有 `/` 单页，购买、订单支付、“我的订单”和管理员“订单管理”均在首页弹窗中完成。无需注册登录；内部账户仅用于订单归属，不提供用户中心。本期没有实际创建或参与投票功能。

访客选择套餐、填写联系信息，通过 `POST /api/platform/checkout` 下单，服务端设置持有订单的 Cookie。“我的订单”仅查询当前浏览器 Cookie 对应的订单，无法换设备自动恢复。请勿清除 Cookie；遗失访问能力时需联系管理员，按订单联系信息核对处理。

当前未接入微信或支付宝支付网关，没有自动对账。按需创建目录并放入真实 PNG 收款码：

- 微信：`public/platform/payment/wechat.png`
- 支付宝：`public/platform/payment/alipay.png`

缺少文件时显示“收款二维码待配置”，请等待配置后再付款，不会生成模拟收款码。用户付款后点“我已付款，申请核实”，只记录申请。管理员须在真实收款账户核实金额与对应关系，再通过首页“订单管理”确认到账，不要只凭截图或申请确认。

发票抬头与税号仅记录开票需求，不自动开票。

## 金额、状态与权益记录

`price` 为整数分。服务端从套餐读取金额和权益，订单保存套餐名称、金额及额度快照；修改套餐不影响历史订单。待支付订单可取消，取消为终态，不能后续确认。已转账却取消的情况需线下联系处理，系统不自动退款。

`platform/payments.js` 的 `confirmPayment` 通过同一事务更新订单、套餐权益余额与流水。重复确认已支付订单不会重复入账，任何一步失败则回滚。仅记录套餐权益入账，本期不执行投票、不消耗权益，也不代表另行开发的投票产品已经交付。

## 回调与未来网关接入

预留的 `POST /api/platform/payments/callback/…` 当前返回 HTTP **501**，不会把任意 POST 当作付款成功。静态收款码本身没有可信支付回调。

未来接入真实网关时，应按平台协议：

1. 验证签名与通知真实性，并核验商户、订单、币种、成功交易状态及订单快照金额。
2. 保存支付平台唯一交易号，建立唯一约束；不能依赖浏览器传入的金额和状态。
3. 在同一原子事务中完成唯一交易号落库、订单更新、权益入账与流水，复用并调整现有确认入口，确保失败回滚、重复通知不重复入账。
4. 按平台协议返回回执，结合主动查询处理漏通知与不确定状态，并完成真实网关测试。

当前没有上述真实支付流程、自动对账、退款和自动开票能力。

## 运行和备份

设置 `PLATFORM_ADMIN_PASSWORD` 后才能登录首页订单管理，未配置不允许登录。仅在 HTTPS 下设置 `COOKIE_SECURE=1`，HTTP 本机调试不要设置。

新销售页默认库为 `data/platform.sqlite`，旧校园模块为 `data/data.json`。SQLite 备份请先正常停服并关闭连接；运行中不可只复制主库而遗漏 WAL 数据。`PLATFORM_DB`、`LEGACY_DATA_DIR` 用于指定独立测试位置，不要用真实活动数据运行破坏性测试。当前无邮箱验证、忘记密码或跨设备订单恢复能力。
